# Pixel Planet

A high-performance, data-driven cellular automata sandbox that runs at near-native speed in the browser via WebAssembly.

Define custom pixel types with unique colours and densities, then wire up their behaviour using a rule system — no hardcoded physics.

---

## Architecture

| Layer | Tech | Role |
|---|---|---|
| **Engine** | Rust → WASM | Grid, rule evaluator, RNG |
| **UI** | React + TypeScript (Vite) | Renderer, entity/rule editor |
| **Bridge** | wasm-bindgen | Zero-copy RGBA buffer sharing |

---

## Quick Start

### Prerequisites

| Tool | Install |
|---|---|
| Rust + Cargo | https://rustup.rs |
| wasm-pack | `cargo install wasm-pack` |
| Node.js ≥ 18 | https://nodejs.org |

### 1 — Build the WASM engine

```powershell
# From the project root
.\rebuild-engine.ps1
```

This compiles the Rust engine to WebAssembly and copies the generated bindings into `ui/src/wasm/`.

### 2 — Run the frontend

```powershell
cd ui
npm install
npm run dev
```

Open the URL printed by Vite (usually `http://localhost:5173`).

## Usage

### Painting

- **Left-click / drag** on the canvas to paint with the selected entity.
- Use the **Brush** slider in the toolbar to change brush radius.
- Select **Erase** to clear pixels back to empty.

### Toolbar

| Control | Description |
|---|---|
| Entity palette | Click an entity button to select it for painting |
| Brush slider | Adjust the paint radius (1–20 cells) |
| ⏸ Pause / ▶ Resume | Freeze or continue the simulation |
| 🧪 Lab | Open the entity & rule editor panel |
| fps counter | Live frame-rate display |

### Lab Panel — New Entity

Create a custom pixel type at runtime:

1. Enter a **name** (e.g. `Lava`).
2. Pick a **colour** with the colour picker.
3. Set a **density** value (higher = sinks below lower-density pixels).
4. Click **+ Add Entity** — it appears immediately in the palette.

### Lab Panel — New Rule

Attach behaviour to any entity without recompiling:

1. Choose the **entity** the rule applies to.
2. **Trigger**: always `OnTick` (evaluated every frame).
3. **Condition**: `NeighborCheck` (check what's adjacent), `Chance` (probability), or `None` (fires unconditionally).
4. **Action**: `Swap` (move), `Transform` (change type), or `Destroy`.
5. Click **+ Add Rule** — it takes effect on the next tick.

**Example — make Lava slowly destroy Sand below it:**
- Entity: Lava, Condition: NeighborCheck Down → Sand, Action: Transform Sand into Lava

## Rule JSON Schema

Rules are serialised to JSON and sent to the WASM engine via `universe.register_rule(json)`.

```json
{
  "entity_id": 4,
  "trigger": "OnTick",
  "condition": {
    "type": "And",
    "checks": [
      { "type": "Chance", "probability": 0.05 },
      { "type": "NeighborCheck", "dir": "Down", "target_id": 1 }
    ]
  },
  "actions": [
    { "type": "Transform", "target_id": 4 }
  ]
}
```

### Condition types

| Type | Fields | Description |
|---|---|---|
| `NeighborCheck` | `dir`, `target_id` | True when the cell in `dir` has entity `target_id` |
| `Chance` | `probability` (0–1) | True with the given probability each tick |
| `And` | `checks[]` | True when all child conditions pass |
| `Or` | `checks[]` | True when any child condition passes |
| `Not` | `check` | Inverts the child condition |

### Directions

`Up` `Down` `Left` `Right` `UpLeft` `UpRight` `DownLeft` `DownRight`

### Action types

| Type | Fields | Description |
|---|---|---|
| `Swap` | `dir` | Exchange this pixel with the neighbour in `dir` |
| `Transform` | `target_id` | Replace this pixel with entity `target_id` |
| `Destroy` | — | Replace this pixel with Empty (id 0) |

## Project Structure

```
PixelPlanet/
├── engine/               # Rust / WASM source
│   └── src/
│       ├── lib.rs        # Universe — public WASM API
│       └── core/
│           ├── entity.rs # EntityDef (id, name, color, density)
│           ├── grid.rs   # Flat 1-D cell grid
│           ├── rule.rs   # Rule AST + condition/action evaluator
│           └── simulation.rs  # Tick loop — rule-driven
├── ui/                   # React / TypeScript frontend
│   └── src/
│       ├── App.tsx       # Main UI — canvas, toolbar, Lab panel
│       ├── types.ts      # Shared TS interfaces for Entity/Rule AST
│       └── wasm/         # Generated by wasm-pack (gitignored)
├── docs/
│   ├── design.txt        # Technical design document
│   └── implementation.txt # Phased implementation plan

```
